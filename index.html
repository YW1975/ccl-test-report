f_route3p(){ local ws u M; ws="$(make_ws)"; u="ROUTEPROBE-$(python3 -c 'import uuid;print(uuid.uuid4().hex[:10])')"; M="${MODELS[$(( (CYCLE-1) % ${#MODELS[@]} ))]}"; local dec gwsrv fam_req fam_srv ldec_ok gw_ok routed; # CF* correlation for the SAME ROUTEPROBE-<uuid> marker, HARD-FAIL on mismatch: # (1) LOCAL: ccl `--model M` → debug callModel decision must == M (ccl routes to M). # (2) GATEWAY: DIRECT litellm curl model=M with the marker → response `model` # family must == M family. The direct-curl response.model is the TRUSTWORTHY # served-model oracle (deepseek-chat→deepseek-chat, qwen3.7-max→qwen3.7-max, # 3/3 reproducible). NOTE: ccl's stream-json model field is NOT trustworthy # (reports kimi-for-coding for a deepseek-chat request) — see BUG-7-ext; we # use the gateway's own response, not ccl's stream-json, as the oracle. (cd "$ws" && env $(gw_env) gtimeout -k 5 50 node "$CLI" --model "$M" --print "reply pong ($u)" --debug-file "$ws/r.log" >/dev/null 2>&1); dec=$(grep -oE "callModel\] model=[^ ]+" "$ws/r.log" 2>/dev/null | head -1 | sed 's/.*model=//'); gwsrv=$(curl -s -m 25 "$GW_URL/v1/chat/completions" -H "Authorization: Bearer $GW_KEY" -H "content-type: application/json" -d "{\"model\":\"$M\",\"messages\":[{\"role\":\"user\",\"content\":\"reply pong $u\"}],\"max_tokens\":8}" 2>/dev/null | python3 -c "import sys,json;print(json.load(sys.stdin).get('model','') or '')" 2>/dev/null); fam_req=$(printf '%s' "$M" | grep -oE '^[a-z]+'); fam_srv=$(printf '%s' "$gwsrv" | grep -oE '^[a-z]+'); ldec_ok=1; [ "$dec" = "$M" ] && ldec_ok=0; gw_ok=1; [ -n "$fam_srv" ] && [ "$fam_srv" = "$fam_req" ] && gw_ok=0; routed=1; [ $ldec_ok -eq 0 ] && [ $gw_ok -eq 0 ] && routed=0; # HARD: both local + gateway must agree local r=$routed; log_result "route-3p" "$([ $r -eq 0 ]&&echo pass||echo fail)" $r "u=$u req=$M localDec=$dec gwServed(directcurl)=$gwsrv fam=$fam_req/$fam_srv" "$([ $routed -eq 0 ]&&echo 1||echo 0)"; rm -rf "$ws"; return $r; }

🔧 BUG-1：--cwd 子命令确定性挂起 已修复

现象

ccl --cwd <dir> workflow run <name> --dry-run 确定性挂起（5/5 exit=124）；cd <dir> && ccl workflow run 正常。原先误判为 flaky，干净复现证明是确定性。

根因（两层）

  1. --cwd 不被子命令遵守：--cwd 的 process.chdir 只写在主 action（main.tsx:1151）。commander 把 workflow 派发为子命令时主 action 不触发 → --cwd 对所有子命令静默失效 → workflow 在原 cwd 找不到 → 挂起。与 gh-33508 --plugin-dir 同类。
  2. headless 子命令打印后不退出（集成测试 oracle 暴露）：--cwd 修好后 workflow 找到了，但从 rich project dir 启动时 preAction 的 init/sinks/MCP/hooks 留下长驻 handle → 进程打印 "succeeded" 后不退出。

修复

  • cli/cwdGlobal.ts：resolveCwdTarget（相对路径对原 cwd 解析）+ 幂等 applyGlobalCwd，照搬 --plugin-dir 先例 wire 进 preAction hook → 所有子命令统一遵守 --cwd。
  • cli/workflow-run.ts：finishHeadless() 写完输出后 flush + process.exit(code) 确定性退出（cron/launchd 友好）。

🔬 BUG-5：app-dev ~15% 失败 = 测试 harness 路径痕迹 已根因 + 已修

现象

真实开发 lane（ccl --print "Create calc.py with add(a,b)..."）在 704 cycle 中 74 pass / 13 fail = 85%，稳定 ~15% 失败。

stream-json 事件流实锤（捕获模型 + 工具调用）

# 所有 case 模型都是 sonnet 且都调用了 Write 工具 —— 不是"没调工具" session cwd（带点） Write 绝对路径 #1 FAIL …/T/tmp.INyCiBY8Ob → …/T/tmp-INyCiBY8Ob/calc.py 点→横线! #4 FAIL …/T/tmp.f5ODx7vPxo → …/T/tmp-f5ODx7vPxo/calc.py 点→横线! #3 PASS …/T/tmp.JY1BBTFhTp → …/T/tmp.JY1BBTFhTp/calc.py 正确 #6 PASS …/T/tmp.TJ6ydZlmuv → …/T/tmp.TJ6ydZlmuv/calc.py 正确 tool_result: "File created successfully at …/tmp-…/calc.py" ← ccl 忠实在错路径创建 真实 cwd（tmp.…）没有文件 → 断言失败

根因

make_ws() 用 mktemp -d 产生带点目录名 tmp.XXXX。sonnet 从 session cwd 构造 Write 绝对路径时，偶尔把目录名里的 . 损坏成 -（tmp.XXX→tmp-XXX），文件落到错误目录。这是测试 harness 用了不真实的路径（带点 mktemp），而非 ccl 不稳定 —— 真实用户项目路径（/Users/name/project）不会触发。

A/B 受控验证（同 prompt / 同模型 / 同网关）

带点 mktemp 路径（tmp.XXXX）: ≈ 6/10 pass（~40% 损坏） 无点干净路径（/proj/...）: 10/10 pass 修复后 make_ws（cclsoakXXXX）: 8/8 pass ← 点是唯一触发因素

修复

tests/stability/soak.sh 的 make_ws() 改用无点模板 mktemp -d "$TMPDIR/cclsoakXXXXXXXX"，使测试路径匹配真实应用场景。

⚖️ 暴露的 Gate 设计张力

app-dev 这类 LLM 创造性 lane 用 ≥99% 阈值 + 累积计数：单次失败需 ~99 次后续连续 pass 才能回到 99%（每 8 cycle 一次 ≈ 数小时），且期间再失败即无法恢复。这意味着真实 LLM 方差下「final gate PASS」可能不可达 —— 这本身是测试 harness 的设计发现（断言/gate 应匹配真实场景）。候选方案（待裁决）：滑窗 gate / LLM-lane 独立阈值 / 硬化 oracle / 接受 LLM 方差。未擅自修改 soak.sh（gate 改动须经 RLL review）。
